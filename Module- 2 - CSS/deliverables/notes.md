Module 2 CSS - Project Documentation and DeliverablesSection 1: Breakpoint Choice and Reasoning Task 20Selected Breakpoints Mobile / Small Screen: 480px min-width Tablet / Medium Screen: 768px min-width Desktop / Large Screen: 1024px min-width Reasoning.
Instead of targeting specific device brand dimensions, the breakpoints were chosen organically based on content wrapping and UI behavior:480px Mobile: Multi-column content, form fields, and navigation links start overlapping or feeling cramped below this point. Stacked layouts work best up to 480px.768px Tablet: At 768px, there is sufficient horizontal space to display navigation items horizontally and shift card components into 2-column grids.1024px Desktop: At 1024px, complex 3-column layouts, sticky sidebars, and full hero sections comfortably render without awkward whitespace or word wrapping.A mobile-first approach was strictly followed using min-width media queries to keep base CSS clean and lightweight.Section 2: Grid vs Flexbox Rebuild Analysis Task 19Experiment Summary
A 2D Dashboard and Card grid layout originally written using CSS Grid with grid-template-columns, minmax, gap was rebuilt entirely using Flexbox with display flex, flex-wrap wrap, flex 1 1 calc.What Was Harder in Flexbox 2D Alignment and Equal Gap Handling: Achieving exact 2D alignment for both columns and rows together required manual flex-basis math and careful margin handling compared to CSS Grid's native gap and grid-template-columns. Spanning Multi-columns and Rows: Making specific items span multiple columns or rows was difficult and hacky in Flexbox, whereas Grid handled it easily using grid-column span 2.Final Conclusion: Which Tool Was Right
CSS Grid was the correct tool for the overall page layout and masonry or dashboard grids, because it is designed for 2D structural layouts rows and columns simultaneously.
Flexbox remains the best tool for 1D content components such as navigation bars, button groups, centering hero sections, and card content alignment.Section 3: CSS Refactoring and BEM Architecture Summary Task 34Overview of Refactoring
All stylesheets were refactored from legacy single-file selectors into a modular, BEM-compliant Block Element Modifier architecture.Key Improvements BEM Naming: Applied explicit block\_\_element--modifier class structure, eliminating high-specificity chained selectors. Custom Properties: Extracted all colors, typography sizes, spacing variables, and z-indexes into a unified variables.css file. DRY Principle Dont Repeat Yourself: Replaced repetitive layout patterns, button resets, and media queries with reusable utility classes and design tokens.Refactor Metrics
